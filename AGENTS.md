# Project Guidelines

## Project goal

Build a full-stack audio censoring application with a FastAPI backend and a React frontend. The intended workflow is to transcribe audio, analyze it to identify content to censor, censor the relevant audio, and patch the edited audio back into the original recording. WhisperX is the planned transcription/alignment technology.

The repository is currently an early Python scaffold. Preserve its existing base structure and architectural patterns; introduce frontend and other components incrementally when a task requires them rather than pre-emptively restructuring the project.

## Engineering expectations

- Implement complete, production-quality behavior with clear, maintainable code and secure defaults. Follow established project patterns and avoid unrelated changes.
- Inspect the existing structure and dependencies before implementation. Add or change dependencies only when required by the current functionality, and keep the lockfile consistent with dependency manifest changes.
- Handle audio and user-provided data with privacy and security in mind; validate inputs and surface errors clearly.
- Validate changes with the smallest relevant tests, checks, or build commands available. Add or update focused tests as functionality is introduced.
- Update the root `progress.md` after each completed task or feature, recording what changed, validation performed, and any remaining manual steps or blockers.
- Ask for clarification when a decision materially affects scope or behavior. Clearly identify any setup or other action the user must perform manually.
- **Code structure (standing rule):** keep `main.py` as app wiring only. Follow the layered layout: routes in `api/` (`router.py`, `schemas.py`, `dependencies.py`), helpers in `utils/`, persistence in `database/` (`models.py`, `session.py`, `crud.py`). Apply clear logic, precise file and folder names, and strict separation of concerns to all new work, at production quality. Whenever a new file or folder is created, give the user a brief synopsis of why it exists and why it is separated.

## Current project state (keep updated)

- **Stack and tooling:** Python 3.12 (`.python-version`), managed with `uv` (`uv add`, `uv run`; keep `uv.lock` consistent). Lint/format with `uv run ruff check .` and `uv run ruff format .`. Tests are `unittest` (pytest is not installed): `uv run python -m unittest discover -s tests`. The `tests/` folder is git-ignored on purpose (internal verification only), so never re-add it to Git.
- **Layout:** `src/ai_censur/` holds `main.py` (app wiring only: lifespan, static mount, `/docs`, includes the routers), `audio_censor.py` (`AudioCensor`), `api/` (`router.py` with `/censor` (response `AudioCreateResponse` also shows `user_list`, `use_beep`, `sound_effect_id`), `GET /audio/{id}` and `PATCH /audio/{id}` (`update_audio`, takes `CensorOptions`, 202), `sound_effect_router.py` with `POST /sfx` (`add_sound_effect`) and `GET /sfx` (`read_all_sound_effects`), `user_router.py` with `POST /signup`, `auth_router.py` with `POST /login`, `schemas.py`, `dependencies.py`), `config.py` (`JWTSettings`, `BrokerSettings` with `BROKER_URL` for the Redis/Celery broker), `services/` (`auth.py` business logic; `audio.py` with `AudioService.update_audio`: applies only the fields sent, compares `user_list` (casefolded set) and queues detect + render if changed, else render only; atomic guarded claim to `processing` (409 otherwise), restores on queue failure; the worker deletes the old censored file after a successful re-render; `sound_effect.py` with `SoundEffectService`: saves the file and its record, removes the file if the DB write fails, and lists through `User.sound_effects`), `worker/` (`tasks.py` holds `celery_app` with task autodiscovery; `processing.py` holds the `AudioTask` base class (its `on_failure` delegates to `AudioCensor.on_failure`), the three tasks `transcribe_audio_task`, `detect_profanity_task`, `render_audio_task`, `queue_audio_reprocessing` (detect + render, or render only), `queue_audio_processing` (a `chain` of the three with `.si(audio_id)`, started with `apply_async()`) and the lazy per-process `AudioCensor`), `utils/` (`constants.py`, `files.py`, `system.py`, `security.py` for Argon2 hashing) and `database/` (`models.py`, `session.py`, `crud.py`, `exceptions.py`). Root folders: `Uploads/` (git-ignored, holds user audio), `SoundEffects/` (git-ignored, will hold user sound effects; the worker trusts only the file name of `SoundEffect.file_path` inside it; uploaded through `POST /sfx`), `samples/` (git-ignored, the user's sample audio files for manual testing; use these instead of the old root `sample.wav`), `tests/`, and `migrations/` with `alembic.ini` (Alembic async migrations; URL comes from `DB_*` in `.env`; schema changes go through `uv run alembic revision --autogenerate -m "<descriptive name>"` then `uv run alembic upgrade head`; first revision `init create users and audio tables`).
- **Audio pipeline:** `AudioCensor` loads WhisperX `small.en` on CPU once per worker process, and provides `transcribe_audio`, `detect_profanity` (better_profanity), `mute_audio(..., beep=False, sound_effect_path=None)` (pydub; a sound effect wins over beep, which wins over silence; the effect is cut or silence-padded to the word length; beep is a 1 kHz tone) and the three stages `run_transcription` (pending -> processing, stores `Audio.transcription`), `run_detection` (default profanity plus `Audio.user_list`, whole words, case and punctuation ignored; stores `flagged`) and `run_render` (uses `use_beep` and the sound effect, sets `censored_file_path` and `completed`). Each stage re-claims the row as `processing` with an atomic status-guarded UPDATE (stage 1 needs `pending`, stages 2-3 need `processing`), so duplicates or finished audio are skipped. `AudioCensor.on_failure(exc, task_id, args, kwargs, einfo)` finds the audio from the task arguments and sets `failed` (never over `completed`); workers do not handle failures themselves. It owns a sync SQLAlchemy engine (asyncpg URL swapped to psycopg2) used only by the Celery worker. Run the worker with `uv run celery -A ai_censur.worker.tasks:celery_app worker --loglevel=info --pool=solo` (plus Redis and the API).
- **API:**
  - `POST /censor` accepts an upload (wav, mp3, m4a, flac, ogg; max 50 MB), saves it to `Uploads/` under its sanitised original name (a numeric suffix is added if the name is taken), stores an `Audio` row as `pending` (project-relative paths such as `Uploads/sample.wav`) and queues the chain transcribe -> detect -> render with the audio UUID; it returns 202 with `AudioCreateResponse` (`id`, `created_at`, `censored_file_path` = null until done, `status`) and 503 (nothing stored) if the broker is down. The worker moves the row `pending -> processing -> completed` (sets `censored_file_path`, saved as `Censored_<name>`) or `failed`. `GET /audio/{audio_id}` returns `AudioRead` (same fields; 404 if unknown). Neither exposes a URL, directory or the uncensored file.
  - `Uploads/` is served statically at `/uploads`.
  - Scalar API docs are at `/docs`. Swagger and ReDoc are disabled.
  - The startup `lifespan` checks ffmpeg, JWT settings and the DB connection (no models are loaded in the API), and disposes the engine on shutdown.
- **Database:** PostgreSQL on localhost:5432, database `Censur`, user `postgres`. Settings come from the git-ignored root `.env` (`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`; template in `.env.example`). Never read, print or commit the password. The database is fully async: SQLAlchemy `AsyncEngine` with the `asyncpg` driver, and `get_session` yields an `AsyncSession` (`psycopg` is blocked here by Windows Application Control, `asyncpg` works). The `Audio` SQLModel (table `audio`: `id` UUID, `created_at`, `updated_at`, `name`, `uncensored_file_path`, `censored_file_path`, `status`, `transcription` JSONB, `use_beep` bool default false, `user_list` text[], `user_id`, `sound_effect_id` FK `sound_effects.id` ON DELETE SET NULL, with a `sound_effect` relationship, lazy `selectin`), the `SoundEffect` SQLModel (table `sound_effects`: `id`, `created_at`, `name`, `file_path`, `user_id` FK CASCADE; `User.sound_effects` relationship (ordered by `created_at`); `/sfx` is token-protected, accepts `.wav/.mp3/.m4a/.flac/.ogg` up to 5 MB with an optional `name` form field (defaults to the file stem), returns only `id`, `created_at`, `name` (never paths), and only ever lists the caller's own; latest revision `00d76ad4be03` "sound effects and audio customization") and the `User` SQLModel (table `users`: `id` UUID, `created_at`, unique `email`, `password_hash`) exist, and the tables are created only by Alembic migrations (`uv run alembic upgrade head`), never by the app; startup just checks the DB connection with `check_database_connection`. `POST /signup` registers users (email lower-cased, password 8-128 chars, hashed with Argon2id through `passlib[argon2]`; 201 `UserRead`, 409 duplicate email).
